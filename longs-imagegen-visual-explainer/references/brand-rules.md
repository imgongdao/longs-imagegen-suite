# 多略视觉化图片 Brand Rules

## 1. Positioning
多略视觉化图片 is an explanation asset, not a decorative asset.
It exists to turn complexity into structured understanding.

Core identity:
- practical
- explanatory
- business-minded
- structured
- information-forward
- visually memorable
- professional, not stiff

## 2. The real standard
The correct benchmark is not “looks good.”
The correct benchmark is:
- did it compress the idea?
- did it reveal the structure?
- did it lower cognitive load?
- did it help the viewer remember?

If it only looks pretty, it failed.

## 3. What 多略 consistently prefers
### 3.1 Structure over decoration
- the main value is organization
- viewers should understand relationships quickly
- boxes, arrows, grouping, layers, or cards are welcome when they clarify the point

### 3.2 Information density, but organized
多略 does not prefer empty minimalism.
It prefers useful density.
This means:
- enough detail to teach
- not so much detail that the image becomes unreadable
- several meaningful blocks are preferred over one vague slogan

### 3.3 Practical framing
Even abstract concepts should feel useful.
The viewer should be able to answer one of these after looking:
- what changed?
- how does it work?
- what should I do?
- what is the difference?
- why does it matter?

### 3.4 Visual relationship expression
多略 visuals should often show:
- process
- comparison
- causality
- decomposition
- hierarchy
- system relationships
- before/after
- hidden logic behind surface events

### 3.5 Stylized surfaces are allowed, but must stay functional
Allowed:
- whiteboard
- napkin sketch
- chalkboard
- A4 paper
- tabletop metaphor
- floating 3D system windows
- clean educational poster

Not allowed:
- background gimmicks that overpower the explanation
- style-first randomness
- excessive texture making text hard to read

## 4. Tone
Preferred tone:
- clear
- smart
- grounded
- lightly ambitious
- educational but not schoolbook-boring
- polished but not corporate dead

Avoid:
- cute for the sake of cute
- fake-deep abstraction
- chaotic startup doodle with no logic
- heavy academic stiffness
- glossy marketing fluff

## 5. Text rules
- text should be short and purposeful
- labels should be direct
- section headings should be stronger than explanatory sentences
- short callouts beat long paragraphs
- keep Chinese copy natural and scannable
- preserve exact brand/product/model names accurately

Avoid:
- paragraph walls
- overloaded captions
- tiny footnotes unless genuinely necessary

## 6. Layout rules
A good 多略 visual usually has:
- one clear title
- one dominant structural frame
- 3–7 key content blocks
- a visible logic for scanning
- enough whitespace or visual separation for readability

Bad signals:
- viewer does not know where to look first
- everything is same size and same weight
- arrows connect everything to everything
- decorative scene dominates actual content

## 7. Background / surface rules
Backgrounds are teaching surfaces, not decorations.
Choose a background because it improves comprehension or memory.

Preferred logic:
- WHITEBOARD for general teaching and processes
- A4 PAPER for report/article explanation
- NAPKIN for founder/idea sketch energy
- CHALKBOARD for principles, frameworks, or classroom tone
- FUTURISTIC FLOATING UI for AI systems, architecture, and product relations
- TABLETOP / OBJECT surfaces when a physical metaphor improves recall

## 8. Color rules
- clarity first
- use restrained but helpful color coding
- use different colors to separate groups or flows when needed
- preserve text contrast strongly
- keep the palette coherent

Avoid:
- too many unrelated accent colors
- dark-on-dark label problems
- neon noise that reduces readability

## 9. Visual metaphor rules
Use metaphors only when they explain.
Good metaphors:
- pipeline
- funnel
- toolbox
- map
- building blocks
- cloud/local split
- bridge
- dashboard
- magnifier/evidence panel

Bad metaphors:
- random robot heads
- meaningless galaxies
- generic circuits with no explanatory role
- unrelated props added for flair only

## 10. Business relevance signal
Even educational visuals should imply relevance.
The viewer should feel some practical payoff:
- this helps me understand a market shift
- this helps me choose a tool
- this clarifies a workflow
- this summarizes a useful concept
- this turns a confusing article into something usable

## 11. Quality bar
A good 多略 visual explainer should make the viewer think:
- “Now I get it.”
- “This is clearer than reading the raw text.”
- “This breaks the topic down intelligently.”
- “I could share this with someone else.”

If the image adds style but not understanding, it failed.
