# Character System

Before first recurring-character render, lock:

```text
character_id
role

gender_or_presentation
face_shape
eye_style
hair_style
hair_color
skin_tone
body_proportion
height_relation
primary_outfit
secondary_outfit
clothing_palette
signature_details
expression_range
render_style
```

## Generality

Characters MAY be:

- boy;
- girl;
- multiple children;
- siblings;
- parent + child;
- teacher + child;
- child + mascot;
- no recurring character.

NEVER assume male protagonist by default.

## Consistency

MUST preserve across pages:

`face + hair + age + body proportion + core clothing palette + signature details + rendering style`

MAY change:

`pose + expression + activity + camera angle + scene + task-specific props`

MAY change clothing only when story/time context requires it; keep identity anchors intact.

## Design Defaults

When no reference exists:

- primary-school-age proportions;
- natural child face;
- expressive but not exaggerated eyes;
- practical everyday clothing;
- simple 2–3 color outfit palette;
- no luxury/fashion emphasis;
- no gender stereotype dependency;
- friendly, curious, capable demeanor.

## Identity References

If a user provides a real child/person reference, follow Harness identity rules.

If a user provides an illustrated character reference, treat it as `identity + style reference` only when assigned.

MUST lock accepted character pages as subsequent consistency references.

## Expression Set

Maintain reusable expressions:

`neutral | curious | thinking | confused | trying | focused | surprised | happy | proud | calm | asking-for-help`

Avoid extreme distress unless explicitly required by educational content.
